# 03. 사람·AI 협업 프로토콜

## 시작 전 공통 규칙

1. 작업자는 `00_project_brief.md`와 `04_decision_ledger.md`를 먼저 읽는다.
2. 데이터·성능·직무 적합성에 관한 미확인 사실은 추정으로 작성하지 않는다.
3. 파일을 수정하기 전 담당 Phase와 검증 방법을 작업 메시지에 적는다.
4. 원본 데이터·비밀키·대형 모델 가중치는 Git에 넣지 않는다.

## 역할 분리

| 역할 | 맡을 작업 | 수정하면 안 되는 영역 |
| --- | --- | --- |
| 데이터 담당 | 다운로드 안내, manifest, EDA, 누수 검사 | 테스트셋을 학습/튜닝에 사용 |
| 모델 담당 | dataset, train, evaluate, checkpoint | 실제 측정 전 지표 문서 |
| 실험 담당 | config, 증강 비교, benchmark | 결과가 없는 수치의 README 반영 |
| UI 담당 | 업로드 검증, 결과·오류 화면 | 모델의 클래스 정의 임의 변경 |
| 문서/QA 담당 | README, case study, 테스트, 주장 검토 | 기술 구현 사실을 추측해 추가 |

## 다른 AI에게 전달할 작업 템플릿

```md
### 작업 목적
<예: Phase 1의 데이터 manifest 생성>

### 읽을 문서
- 00_project_brief.md
- 02_phase_plan.md의 Phase <번호>
- 04_decision_ledger.md

### 허용 범위
<수정 가능한 폴더와 파일>

### 금지 사항
- 측정하지 않은 수치·실제 현장 적용 주장 추가 금지
- test set을 모델 선택에 사용 금지

### 완료 기준
<실행 명령, 생성 파일, 확인할 테스트>

### 결과 보고 형식
- 변경 파일:
- 실행한 명령:
- 실제 결과:
- 한계/미완료 항목:
```

## 변경 검토 규칙

- 코드 변경은 `무엇을`, `왜`, `어떻게 검증했는지`를 PR 또는 작업 기록에 남긴다.
- 수치가 바뀌면 데이터 버전·config·commit·실행 환경을 같이 갱신한다.
- 상충하는 변경이 있으면 구현을 진행하지 말고 `04_decision_ledger.md`에 선택지를 기록한다.
